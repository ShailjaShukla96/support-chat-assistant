# Data Model: Caramel AI Tech Support Chat Assistant

**Spec**: [spec.md](spec.md) | **Plan**: [plan.md](plan.md) | **Research**: [research.md](research.md)

Storage is embedded H2 (file mode) through Spring Data JDBC (see research R8). Identifiers are random
UUIDs generated by the backend. Timestamps are UTC instants.

## Entities

### ChatSession

One customer's conversation (spec: Chat Session).

| Field | Type | Rules |
|-------|------|-------|
| `id` | UUID | Primary key. Returned to the client and used as the session handle. |
| `userRef` | string, nullable | Optional external session/user ID passed by the host site (FR-017). Max 128 chars. Never used to personalize answers. |
| `createdAt` | instant | Set on creation. |

A session has no end state in v1: the client discards its `id` when the customer closes the window or starts a
new chat (spec assumption). Messages for a session are only ever read by that `id`, which enforces FR-004.

### Message

A single customer or assistant message (spec: Message).

| Field | Type | Rules |
|-------|------|-------|
| `id` | UUID | Primary key. Ratings point at assistant messages by this ID. |
| `sessionId` | UUID | FK to ChatSession. Required. |
| `role` | enum `USER`, `ASSISTANT` | Required. |
| `text` | string | Required. User text: 1 to 2,000 chars after trimming. Assistant text: stored as returned to the customer (marker stripped, output guard applied). |
| `outcome` | enum, nullable | Assistant messages only: `ANSWERED`, `NO_ANSWER`, `UNAVAILABLE`, `BLOCKED`, `ESCALATED`. Null for user messages. |
| `escalationOffered` | boolean | Assistant messages only. True for `NO_ANSWER`, `UNAVAILABLE`, `BLOCKED`. |
| `requestId` | string, nullable | Request ID that produced the message (links to logs). |
| `latencyMs` | integer, nullable | Assistant messages produced by a model call. |
| `promptTokens` | integer, nullable | From model usage metadata when provided. |
| `completionTokens` | integer, nullable | From model usage metadata when provided. |
| `createdAt` | instant | Ordering key within a session. |

**Outcome meanings**

| Outcome | Meaning | Replayed to model as history? |
|---------|---------|-------------------------------|
| `ANSWERED` | Grounded answer returned | Yes |
| `NO_ANSWER` | Model reported it cannot answer; marker stripped | Yes |
| `UNAVAILABLE` | Provider failed or timed out; friendly message shown | No |
| `BLOCKED` | Output guard replaced the reply | No |
| `ESCALATED` | Fixed confirmation sent after a free-text human request | No |

**History rule**: the prompt contains the last 20 messages of the session whose outcome is null (user),
`ANSWERED`, or `NO_ANSWER`, in `createdAt` order.

### EscalationRequest

A recorded request for a human agent (spec: Escalation Request).

| Field | Type | Rules |
|-------|------|-------|
| `id` | UUID | Primary key. |
| `sessionId` | UUID | FK to ChatSession. Required. |
| `reason` | enum | `CUSTOMER_REQUESTED` (button or detected phrase), `ASSISTANT_UNSURE`, `PROVIDER_UNAVAILABLE`. |
| `transcript` | text (JSON array) | **Immutable snapshot** at request time: ordered list of `{role, text, createdAt}` for all messages of the session. Never edited. |
| `status` | enum | `NEW` on creation; `ACKNOWLEDGED` once an agent marks it (reserved, set only by future agent tooling). |
| `requestId` | string | Request that created it. |
| `createdAt` | instant | Time of the request (FR-009). |

Multiple escalations per session are allowed. Each stores its own snapshot (spec edge case: customer keeps
chatting after escalating).

### ResponseRating

A helpful / not-helpful rating (spec: Response Rating).

| Field | Type | Rules |
|-------|------|-------|
| `id` | UUID | Primary key. |
| `messageId` | UUID | FK to Message. **Unique**: one rating per message. Must reference an `ASSISTANT` message. |
| `value` | enum `UP`, `DOWN` | Required. |
| `updatedAt` | instant | Upsert: a repeat rating replaces the value and time (User Story 4, scenario 2). |

### SupportContentItem (not stored in the database)

A FAQ, document, or troubleshooting guide (spec: Support Content Item). Read from Markdown files at startup.

| Field | Type | Rules |
|-------|------|-------|
| `id` | string | File name without extension. Unique. |
| `title` | string | First `#` heading, else the file name. |
| `text` | string | Full Markdown body. |

Total size across items MUST NOT exceed `app.knowledge.max-chars` (default 60,000); startup fails otherwise.

## Relationships

```text
ChatSession 1 ──< Message 1 ──0..1 ResponseRating
ChatSession 1 ──< EscalationRequest   (transcript snapshots Messages at creation time)
SupportContentItem: read-only, global, placed in the system prompt
```

## State transitions

- `Message.outcome` is set once, when the assistant message is created, and never changes.
- `ResponseRating.value`: `none → UP | DOWN`, then `UP ⇄ DOWN` any number of times.
- `EscalationRequest.status`: `NEW → ACKNOWLEDGED` (the second state is not reachable in v1).

## Derived metrics (queries, not columns)

| Spec criterion | Query idea |
|----------------|-----------|
| SC-001 resolved without escalation | Sessions with at least one user message and no EscalationRequest, divided by all sessions with at least one user message |
| SC-002 helpful share | `UP` ratings divided by all ratings |
| SC-003 median latency | Median of `Message.latencyMs` for assistant messages with a model call |
| SC-005 transcripts recorded | Count of EscalationRequest with empty `transcript` must be 0 |

## Schema notes

- `schema.sql` is applied on startup. Indexes: `message(sessionId, createdAt)`, `escalation_request(createdAt)`,
  unique `response_rating(messageId)`.
- No column stores API keys, the system prompt, or provider error bodies.
